요약

네 가지 결정

  1. 이번 주 안에 Gemini 모델을 교체합니다.analyze-video와 ingest-orders가 모두 2.5 계열(Flash, Flash-Lite, Pro)을 씁니다. 2.5 Flash는 이르면 10월 16일 종료로 공지됐고, 그 전에 404를 받은 사례도 있습니다. 폴백 모델까지 같은 계열이라 한꺼번에 멈출 수 있습니다.
  2. 자막은 우리 서버가 긁지 않고 Gemini가 읽게 합니다.엣지 함수에서 유튜브 자막을 가져오는 방식은 데이터센터 IP 차단과 PO 토큰 요구 때문에 불안정합니다. 2026년 9월 나온 에이전틱 영상 이해(mediaProcessing: "AGENTIC")는 구글 서버 안에서 자막부터 읽고 필요한 장면만 봅니다.
  3. 설명란과 댓글은 공식 API로 먼저 가져옵니다.YouTube Data API는 영상당 2유닛(하루 무료 10,000유닛)으로 설명란·챕터·길이·댓글을 줍니다. 설명란에 레시피가 다 있으면 영상을 보지 않고 텍스트만으로 끝냅니다.
  4. 사용자를 기다리게 하지 않습니다.분석을 비동기 작업으로 바꿔 1초 안에 미리보기 카드를 보여주고, 진행 상황은 Supabase Realtime으로 갱신합니다. 다른 화면으로 가도 분석은 계속됩니다.

자막 추출 방법 비교

레시피에 필요한 정보는 대부분 말(자막)과 설명란에 있습니다. 화면에서만 알 수 있는 정보(화면 글씨로만 나오는 양, 내레이션 없는 영상의 동작)는 일부입니다. 그래서 텍스트를 먼저 쓰고 영상은 모자란 부분에만 쓰는 것이 비용의 핵심입니다. 10분 영상 기준으로 영상 입력은 약 17만 토큰, 같은 영상의 자막은 약 3~4천 토큰이라 40배 넘게 차이 납니다.

자막은 구글이 읽게 하는 편이 가장 싸고 안정적입니다

우리 서버에서 자막을 가져오는 방법은 모두 유튜브의 봇 차단과 싸워야 합니다. Gemini에 유튜브 URL을 넘기면 구글이 자기 서버에서 영상을 읽으므로 이 문제가 없습니다. 에이전틱 모드는 그 안에서 get_transcript로 자막을 먼저 읽고, get_frames(start, end, fps)로 필요한 구간의 프레임만 봅니다. 우리가 직접 만들려던 ‘자막 먼저, 영상은 필요할 때만’ 로직을 모델이 대신 수행합니다.

설계

권장 파이프라인

위에서부터 싼 단계 순서로 시도하고, 앞 단계에서 품질 기준을 넘으면 거기서 끝냅니다. ①~③은 요청 안에서 처리해 1초 안에 미리보기를 돌려주고, ④~⑥은 백그라운드에서 돌립니다.

    적중하면 종료
  2. 2
    로그인·한도 확인$0

    캐시에 없는 새 분석만 로그인을 요구하고 월 한도(예: 가족당 60건)에서 차감합니다. 캐시 적중은 무료이고 한도에 넣지 않습니다.

  3. 3
    메타데이터와 사전 검사$0 · 2유닛 · 약 0.5초

    videos.list(snippet, contentDetails, status)와 commentThreads.list(관련성 상위 30개)를 부릅니다. 비공개·삭제 영상은 unavailable, 40분 초과는 too_long으로 사용자 확인을 받습니다. 설명란에서 챕터(00:00 형식)를 뽑고, 레시피가 다 적혀 있는지 정규식으로 판별합니다. 여기까지 끝나면 제목·채널·썸네일·길이로 미리보기 카드를 바로 돌려줍니다.

  4. 4
    텍스트 빠른 경로 (조건부)약 $0.004 · 3~5초

    설명란에 수량 표기가 5개 이상이고 번호 붙은 단계가 3개 이상일 때만 실행합니다. gemini-3.1-flash-lite, thinking 최소, 구조화 출력으로 설명란·챕터·댓글을 정리합니다. 조건을 미리 걸러서, 텍스트 단계 값을 내고 다시 영상 단계로 가는 이중 지출을 줄입니다.

    품질 기준 통과 시 종료
  5. 5
    에이전틱 영상 분석약 $0.008~0.015 · 수십 초

    gemini-3.5-flash-lite에 유튜브 URL을 mediaProcessing: "AGENTIC"으로 넘깁니다. 설명란·챕터·댓글과 ④의 부분 결과를 힌트로 주고 “빈 칸을 채우고 단계마다 영상 시간을 달라”고 요청합니다. 레시피와 시청자 팁(댓글 요약)을 한 번의 호출로 받아 Qwen 호출을 없앱니다.

    품질 기준 통과 시 종료
  6. 6
    폴백약 $0.017

    에이전틱 호출이 오류를 내면 고정 샘플링(mediaResolution: LOW, fps: 0.5)으로 한 번만 다시 시도합니다. 그래도 실패하면 설명란 기반 부분 결과를 ‘보정 모드’로 돌려주고, 확인이 필요한 칸을 표시합니다.

품질 기준

요리 영상이고, 재료 3개 이상, 재료 중 수량이 채워진 비율 70% 이상, 단계 3개 이상, confidence 0.75 이상. 기준은 평가 세트로 조정합니다(아래 구현 스케치 7번).

비동기 처리

③까지 끝나면 analysis_jobs 행을 만들고 바로 응답합니다. ④~⑥은 EdgeRuntime.waitUntil()로 이어서 실행하며 단계가 바뀔 때마다 그 행을 갱신합니다. 앱은 Supabase Realtime으로 행을 구독해 진행 단계를 그립니다. 같은 영상을 두 사람이 동시에 넣으면 진행 중인 작업에 합류합니다. 무료 플랜의 워커 수명은 150초(유료 400초)이고 백그라운드 작업도 이 한도 안에서만 돌므로, 영상 단계 타임아웃은 100초로 잡습니다.

모델 선택

에이전틱 모드는 Gemini 3.7 Flash, 3.6 Flash, 3.5 Flash-Lite에서 지원됩니다. 가장 싼 3.5 Flash-Lite로 시작하고, 평가 세트에서 부족하면 3.6/3.7 Flash로 올립니다. 모델 ID와 가격은 자주 바뀌므로 용도별 환경 변수(GEMINI_TEXT_MODEL, GEMINI_VIDEO_MODEL)로 분리하고, 배포 전 ListModels로 실제 ID를 확인합니다.

가족 규모라면 무료 등급으로도 운영됩니다

Gemini API 무료 등급은 Flash와 Flash-Lite 계열을 제공하고, 유튜브 영상은 하루 8시간까지 처리합니다. 하루 수십 건 이하라면 충분합니다. 다만 무료 등급 입력은 구글 제품 개선에 쓰일 수 있습니다. 공개 영상 분석에는 무료 키를 써도 되지만, 주소·이름이 담길 수 있는 주문 메일 파싱(ingest-orders)은 유료 키를 쓰는 편이 안전합니다.

// analyze-video/index.ts — 요청 안에서는 ③까지만 하고 바로 응답

if (!(await consumeQuota(supabase, userId))) return json(failure("edge", "quota_exceeded"), 429);

const meta = await fetchMeta(videoId, ytKey);                  // ③ videos.list (1유닛)
if (!meta || meta.privacy !== "public") return fail("unavailable");
if (meta.durationSec > 40 * 60 && !body.confirmLong) return fail("too_long");

const job = await joinOrCreateJob(supabase, videoId, userId, previewOf(meta));
EdgeRuntime.waitUntil(runPipeline(job, meta));                 // ④~⑥ 백그라운드
return json({ ok: true, source: "job", jobId: job.id, preview: job.preview });
// 백그라운드 단계
async function runPipeline(job, meta) {
  const hints = {
    title: meta.title, description: meta.description,
    chapters: parseChapters(meta.description),
    comments: await fetchTopComments(job.videoId, ytKey, 30),   // commentThreads.list (1유닛)
  };
  let result = null;
  if (looksLikeFullRecipe(meta.description)) {
    await setStage(job, "text");
    result = await structureFromText(hints);                  // ④ 3.1 Flash-Lite
  }
  if (!passesGate(result)) {
    await setStage(job, "video", result);                   // 부분 결과를 먼저 화면에
    result = (await analyzeAgentic(job.videoId, hints, result))   // ⑤ 3.5 Flash-Lite AGENTIC
          ?? (await analyzeFixedLow(job.videoId, hints));          // ⑥ LOW + fps 0.5
  }
  await finishJob(job, result);   // video_analyses upsert + analysis_runs 기록
}

3. 설명란 판별, 챕터, 품질 기준

const AMOUNT = /\d+(?:[.,/]\d+)?\s*(?:g|kg|ml|L|컵|큰술|작은술|T|t|스푼|숟가락|개|알|쪽|줌|꼬집|장|모|대|마리)/g;
const STEP = /^\s*(?:\d+[.)]|[①-⑳]|STEP\s*\d)/gim;

function looksLikeFullRecipe(desc = "") {
  return (desc.match(AMOUNT) || []).length >= 5 && (desc.match(STEP) || []).length >= 3;
}

function parseChapters(desc = "") {               // "03:20 양념장 만들기" → { sec: 200, title }
  return [...desc.matchAll(/^\s*(?:(\d{1,2}):)?(\d{1,2}):(\d{2})\s+(.+)$/gm)]
    .map(([, h, m, s, title]) => ({ sec: (+h || 0) * 3600 + +m * 60 + +s, title: title.trim() }));
}

function passesGate(r) {
  if (!r?.isRecipe) return false;
  const filled = r.ingredients.filter((i) => i.amount).length;
  return r.ingredients.length >= 3 && filled / r.ingredients.length >= 0.7
      && r.steps.length >= 3 && r.confidence >= 0.75;
}

기능

기능 개편

지금 앱에서 불편한 점

  • 하단 탭 5개 중 2개가 재고(냉장고, 실온보관), 1개는 홈 검색창과 같은 검색, 1개는 한 번 쓰고 마는 동작(분석)입니다.
  • 분석하는 동안 최대 90초 화면이 멈춰 있고, 실패하면 빈 칸이 많은 긴 입력 폼이 나옵니다.
  • 분석 미리보기가 모든 필드를 입력칸으로 보여줘서 어디를 확인해야 하는지 알기 어렵습니다.
  • ‘유튜브 앱에서 공유하기 → 이 앱 선택’ 안내가 있지만 manifest에 share_target이 없어 동작하지 않습니다. 앱은 url·v만 읽는데 유튜브 앱은 링크를 text로 보냅니다.
  • 가족 앱인데 데이터가 계정 단위라 가족이 같은 레시피북을 함께 쓸 수 없습니다. 구성원은 태그 역할만 합니다.
  • 냉장고 추천은 있지만 부족한 재료를 장보기로 넘기는 흐름이 없고, Gmail 자동입고는 설정 깊숙이 있습니다.
  • 설정 첫 화면에 Function URL, anon key, 목업 모드처럼 개발할 때만 필요한 항목이 보입니다.

기획서 v0.4 2026-05-20 상업화 대비

유튜브 요리 영상을
가족 레시피로 정리해주는 앱

URL 하나 던지면 Gemini가 재료·순서·팁을 정리합니다. 가족 구성원별로 좋아하는 메뉴를 모으고, 같은 영상은 한 번만 분석해 비용을 줄입니다.

📌 v0.4 변경점 — v0.3을 실제 운영 가능한 MVP 기준으로 다시 좁혔습니다.
  • Gemini YouTube URL 직접 전달은 preview 기능으로 명시하고, 가격·레이트리밋·정책 변경 리스크를 운영 가정에 추가
  • Gemini 호출은 Supabase Edge Function → REST API를 기본 경로로 고정해 API 키와 교체 가능성을 보호
  • 실패 사유를 비요리·비공개/삭제·스키마 실패·내용 부족·길이 초과·API 장애로 세분화
  • video_analyses에 품질 상태(status, needs_review, 신고/채택 카운트)를 추가해 공유 캐시 오염을 줄임
  • MVP에서 결제, Family 플랜, 웹 공유 뷰어, 오프라인 조리, 장보기, TTS는 제외하고 분석·보정·저장 루프에 집중

01개요

왜 만드는가, 무엇을 해결하는가

요리 유튜브를 즐겨보지만 매번 영상을 다시 돌려보며 재료와 순서를 받아 적기 번거롭다. 이 앱은 URL 하나로 Gemini가 영상을 분석해 재료·조리 순서·팁을 구조화된 레시피로 만들어주고, 가족 구성원(예: 딸, 아빠)별로 즐겨찾기를 나눠 저장한다. 카테고리(한식/양식/일식/중식 등)로도 필터링할 수 있다.

핵심 가치는 마찰 없는 입력이다. 유튜브 앱에서 공유하기 한 번이면 분석이 자동 시작된다.

🍅
차별화 한 줄 — 한국 가정식·한국어 유튜브 특화 + "가족 구성원" 컨셉 + 영상 공유 캐싱으로 압도적 비용 우위.

수동 보정 모드

모든 분석 결과는 편집 가능하다. Gemini가 빈 단계를 남겼거나 재료를 누락했을 때, 사용자가 인라인으로 수정·추가할 수 있다. 보정한 결과는 recipes의 개인 사본에 저장되어 캐시 원본(video_analyses)에는 영향을 주지 않는다.

⚠️
중요 정책 — Gemini가 실패해도 사용자 월 분석 카운트는 차감하지 않는다. "돈 내고 분석했는데 결과 없음" 경험을 차단해야 신뢰가 무너지지 않는다.

05데이터 모델

Supabase Postgres · RLS 격리 · 영상 분석은 공유 캐싱

모든 사용자별 테이블에 user_id를 두고 Row Level Security(RLS)로 격리. 영상 분석 결과는 사용자 간 공유 캐싱.

테이블주요 컬럼비고
usersid, email, plan(free/pro/family), monthly_analyses_used, monthly_reset_at, created_atSupabase Auth와 1:1
membersid, user_id, name, emoji, color, allergies[]가족 구성원, 사용자별 격리
categoriesid, user_id(nullable), name, icon, is_default기본 카테고리는 user_id NULL · 공유
video_analyses 공유youtube_video_id (PK), title, raw_recipe(JSONB), suggested_category, confidence, status, needs_review, failure_reason, accepted_count, reported_count, last_validated_at, thumbnail_url_yt, analyzed_at, model_version같은 영상은 한 번만 분석. 품질 상태를 두어 낮은 confidence·신고 누적 캐시를 재검증 v0.4
analysis_failures NEWid, youtube_video_id, user_id, reason(enum), occurred_at실패 케이스 로깅 — 디버깅·모델 튜닝용
recipesid, user_id, video_id(→video_analyses), title, category_id, servings, cook_time_min, custom_notes, is_favorite, created_at사용자 개인 사본 (커스터마이즈 가능). 공유 토큰은 v1.1 이후로 분리 v0.4
recipe_ingredientsrecipe_id, name, amount, unit, sort_order사용자가 수정 가능
recipe_stepsrecipe_id, order, text, timestamp_sectimestamp는 원본 영상 시점
recipe_membersrecipe_id × member_id좋아하는 사람 다대다
households v2id, name, owner_user_id가족 계정 공유 (v2 확장 대비)
household_members v2household_id × user_id, role같은 가족 계정에 여러 로그인
💰
비용 절감 핵심 — recipes.video_id로 video_analyses를 참조. 100명이 같은 백종원 영상을 분석해도 Gemini 호출은 1번. 인기 영상은 99%+ 캐시 적중 예상.

썸네일 정책 v0.4 유지

YouTube 썸네일은 자체 호스팅하지 않고 https://i.ytimg.com/vi/{video_id}/hqdefault.jpg 직링크 사용. 저작권 회피 & Storage 비용 절감. 자체 캡처(step-images/)는 v1.3 사용자 업로드용으로만 유지.

07공유 인텐트 처리

유튜브 → 우리 앱으로 들어오는 핵심 진입로

유튜브 앱의 공유 메뉴에 이 앱이 노출되려면 AndroidManifest.xml에 인텐트 필터를 등록해야 한다.

<activity android:name=".MainActivity" ...>
  <intent-filter>
    <action android:name="android.intent.action.SEND" />
    <category android:name="android.intent.category.DEFAULT" />
    <data android:mimeType="text/plain" />
  </intent-filter>
</activity>

앱 시작 시 인텐트의 EXTRA_TEXT에서 YouTube URL 패턴을 추출:

const re = /(?:youtube\.com\/watch\?v=|youtu\.be\/|youtube\.com\/shorts\/)([\w-]+)/;
const videoId = sharedText.match(re)?.[1];
if (videoId) router.push(`/analyze?v=${videoId}`);

Capacitor는 capacitor-plugin-send-intent 또는 @capacitor-community/intent로 위 흐름을 JS 측에서 처리할 수 있다.

아웃바운드 공유 v1.1 이후

MVP에서는 저장 루프를 우선 검증한다. 이후 저장된 레시피에 share_token을 발급해 recipe.app/r/{token} 형태 딥링크를 만들고, 미설치자에겐 웹 뷰어로 폴백한다.

08Gemini 연동 방식

모델 선택, 캐싱 플로우, 출력 스키마
  • 모델: gemini-2.5-flash (속도/비용 균형) — confidence 부족 또는 빈 결과 시 gemini-2.5-pro로 1회 폴백
  • 입력: YouTube URL을 직접 전달해 영상·음성을 처리하되, 이 기능은 preview 성격이므로 가격·레이트리밋·정책 변경 가능성을 운영 리스크로 둔다
  • 출력 스키마 강제: responseSchema로 JSON 구조 고정, is_recipe·confidence 포함
  • 호출 경로: 클라이언트 → Supabase Edge Function → Gemini API
    이유: API 키 보호, 캐싱 조회/저장, 사용량 카운트, 요금제 한도 체크를 서버에서 수행. Edge Function은 SDK보다 REST 호출을 기본값으로 두어 Deno 런타임과 API 변경에 대응한다
  • 캐싱 플로우:
    1. 클라이언트가 YouTube URL 전송
    2. Edge Function이 video_id 추출 후 video_analyses 조회
    3. 히트 → 즉시 반환 (무료, 0초)
    4. 미스 → 요금제 한도 체크 → Gemini Flash 호출 → 검증 → 결과 저장 → 반환
    5. 실패 → Pro 모델 1회 재시도 → 그래도 실패면 analysis_failures 로깅 + 카운트 차감 X v0.4
{
  "is_recipe": "boolean",
  "confidence": "number (0~1)",
  "title": "string",
  "suggested_category": "한식 | 양식 | 일식 | 중식 | 디저트 | 기타",
  "servings": "number",
  "cookTimeMin": "number",
  "ingredients": [{ "name": "string", "amount": "number", "unit": "string" }],
  "steps":       [{ "order": "number", "text": "string", "timestampSec": "number" }],
  "tips":        ["string"]
}

분석 후 결과를 미리보기 화면에 띄우고, 사용자가 카테고리·구성원만 확인/조정해 저장한다 (suggested_category가 디폴트로 채워짐, 사용자 변경 가능).

앱 ↔ Edge Function 응답 계약 v0.4

{
  "ok": true,
  "source": "cache | gemini | mock",
  "analysis": { "...": "위 raw_recipe 스키마" },
  "failure": null,
  "quota": { "charged": true, "remaining": 11 }
}

실패 시에도 같은 형태를 유지하되 ok: false, failure.reason, failure.message, quota.charged: false를 반환한다. 클라이언트는 이 계약만 보고 미리보기·보정·실패 안내를 처리한다.

09기술 스택

Capacitor + 웹앱이 1인 운영에 최적
✅ 추천: Capacitor + 웹앱 (HTML/CSS/JS)

eventbot과 동일한 패턴이라 학습/유지보수 비용 0. Gemini는 Edge Function에서 REST로 호출해 API 키와 제품 변경 리스크를 격리. UI 반복이 가장 빠르고, 공유 인텐트는 플러그인으로 해결.

옵션장점단점
Capacitor + 웹앱빠른 개발, eventbot과 동일 스택, 어디서나 디버깅네이티브 성능·기능 제약 (본 앱엔 무관)
Kotlin + Compose정석 안드로이드, 성능 최상학습/빌드 사이클 부담, 1인용엔 과함
Flutter크로스플랫폼안드로이드만 쓸 거면 이득 없음, 새 언어

주요 라이브러리

  • @capacitor/core, @capacitor/android
  • Gemini REST API 우선, 필요 시 @google/genai 검토 — Edge Function 서버 측에서만 호출
  • @supabase/supabase-js — DB · Storage · Edge Functions
  • capacitor-plugin-send-intent — 공유 인텐트 수신
  • @capacitor/preferences + IndexedDB — v1.2 오프라인 레시피 캐시 후보
  • Web Speech API — v1.2 조리 모드 TTS 후보

10리스크 & 대응 신규

출시 전후 마주칠 주요 리스크
HIGH
Gemini YouTube URL preview 의존 YouTube URL 직접 분석은 MVP 속도를 크게 높이지만, preview 성격이라 가격·레이트리밋·지원 범위가 바뀔 수 있다.
Gemini 호출을 Edge Function 한 곳에 격리하고, REST 요청/응답 계약만 앱과 공유한다. 장애 시 수동 입력·부분 보정으로 저장 루프는 유지한다.
HIGH
자막 없는 영상 분석 정확도 한국 요리 유튜브에는 음악·자막 없이 핸즈 클로즈업만 있는 영상이 의외로 많다. Gemini가 영상만으로 정확한 재료량 추출이 어려울 수 있음.
MVP 착수 전 20개 영상 샘플 테스트로 정확도 측정. confidence < 0.5는 자동으로 보정 모드 진입. 부정확한 경우도 "수정해서 쓰는" UX로 처리하면 신뢰 유지 가능.
HIGH
YouTube 정책 변동 Gemini가 영상 콘텐츠를 분석하는 행위와 YouTube 접근 가능 범위는 정책·제품 변경의 영향을 받는다. 비공개·일부공개·삭제·지역제한 영상은 실패로 처리한다.
"영상을 재배포하지 않고 사용자 개인 메모 추출" 컨셉 유지. 출처(원본 링크) 항상 명시. 정책 변경 시 즉각 대응할 수 있도록 클라이언트가 아닌 서버 측에서 Gemini 호출(스위치 가능).
MED
캐시 오염 먼저 분석한 사용자가 부정확한 결과를 받으면 그 캐시가 다른 사용자에게도 노출됨.
캐시는 읽기 전용 원본으로 두고, 각 사용자가 자기 recipes 사본에 수정한다. status, needs_review, accepted_count, reported_count로 품질을 추적하고 confidence < 0.7은 재검증 후보로 둔다.
MED
Gemini 비용 폭증 유료 전환 전 무료 사용자가 신규 영상만 계속 분석할 경우.
Free 한도 + 영상 길이 1시간 제한 + 동일 사용자 1분 내 중복 분석 차단(Rate limit). Edge Function에 일일 글로벌 캡 설정.
MED
콜드스타트 — 캐시 적중률 낮음 초기 사용자는 캐시가 없어 매번 신규 분석 → Free 5건이 1~2일에 소진.
출시 6개월간 Free 12건 → 캐시 누적 후 5건으로 점진 축소. 또는 인기 한국 요리 영상 100~200개 프리 시드(본인이 직접 실행해 캐시 채우기).
LOW
결제 도입 복잡도 Play 인앱결제 vs 자체 결제 선택.
MVP에서는 결제를 제외한다. 베타에서 결제 의사를 확인한 뒤 Play 인앱결제를 우선 검토하고, 자체 결제는 v2 이후로 미룬다.

13상업화 전략

차별화 · 가격 · 검증 단계

차별화 포인트

  • 한국 가정식·한국어 유튜브 특화 — 글로벌 앱(ReciMe, Crouton 등)이 못 따라오는 영역
  • 가족 구성원 컨셉 — 개인 중심 레시피 앱 시장에서 유일한 차별점
  • 유튜브 공유 인텐트 진입 — 마찰 최소화, 사용자가 영상 본 직후 즉시 저장
  • 영상 공유 캐싱 — 인기 영상은 0초·0원으로 즉시 결과 제공, 경쟁사 대비 압도적 비용 우위

추가 수익 가능성

  • 식자재 커머스 어필리에이트 — 마켓컬리·쿠팡 "이 레시피 재료 한 번에 주문" 링크
  • 크리에이터 도구 (B2B) — 요리 유튜버에게 자신의 채널 전용 레시피 카드 자동 생성
  • 광고는 지양 — UX 해침, 수익 미미

출시 전 검증 단계

  1. 샘플 정확도 실측 (1주) — 한국 요리 영상 20개 분석, 재료/단계 정확도 70%+ 확인 v0.4
  2. 본인 사용 (1~2개월): MVP 완성 후 매일 쓰는지 검증. 안 쓰면 상업화 보류
  3. 지인 베타 (5~20명): 친척·친구에게 무료 배포, 리텐션·페인포인트 수집
  4. 클로즈드 베타: 한국 요리 커뮤니티(82쿡, 디시 요리갤 등)에 소규모 모집, 결제 의사 측정
  5. Play Store 정식 출시: ASO, 한국 요리 유튜버 협업 마케팅

법적/운영 고려사항

  • 저작권: 영상 자체를 재배포하지 않고 "레시피 정보"만 추출 · 출처 명시 → 일반적으로 fair use 범위. 사전 법률 검토 권장
  • 썸네일: i.ytimg.com 직링크만 사용 (캐시 X) → 직접 호스팅 리스크 회피
  • 개인정보처리방침·이용약관 필수
  • 결제: MVP 제외. 결제 의사 검증 후 Play Store 인앱결제 우선, 자체 결제는 v2 이후 검토

기획서 v0.5 2026-05-21 피벗 — 사적 도구

유튜브 요리 영상을
우리의 가족 레시피로

가족과 가까운 친구 몇 명만 초대해서 함께 쓰는 사적 요리 노트. 상업화 욕심을 버린 대신, 경쟁사들이 검증한 좋은 기능을 마음껏 흡수합니다.

🔄 v0.5 변경점 — 상업화에서 사적 도구로 피벗
  • 경쟁사 4종(레시피오·해먹으리·Recify·쉐프토리) 등장 → "한국어 유튜브 특화" 차별점 무너짐. 본인·가족·친구만 쓰는 사적 초대제 도구로 framing 재정의
  • 요금제·신고·캐시 품질 시그널·결제 등 상업화 흔적 제거. Gemini 비용은 본인 부담
  • 경쟁사 강점 통합: 상황 태그(홈파티/혼밥) · 냉장고 모드 · 칼로리·영양 자동 · 컬렉션 폴더 · 인스타·틱톡 진입로
  • households 모델을 v2가 아닌 day 1으로. 친구는 자기 가구를 갖고 독립 격리
  • 인증 단순화: 본인이 초대 링크 발급, 가입은 자유롭게 두되 본인이 모니터링

01개요 · 피벗 배경

왜 사적 도구로 방향을 틀었나

당초 기획은 한국 가정식·한국어 유튜브 특화 + 가족 구성원 컨셉 + 영상 공유 캐싱으로 상업화 가능성을 노렸다. 그러나 v0.5 시점에 시장조사 결과 같은 컨셉의 한국 앱이 4개 이상 존재하고, 그중 레시피오는 30,000+ 큐레이션·AI 맞춤·냉장고 관리까지 무료로 제공한다는 사실을 확인했다.

이 상황에서 후발 주자로 상업화 경쟁을 시도하는 것은 비효율적이다. 대신 "본인이 매일 쓰는 도구 + 가까운 사람 몇 명과 공유"라는 명확하고 작은 목표로 재정의한다. 광고·결제·ASO·신고 시스템 같은 부담을 모두 떨궈내고, 그만큼 본인 사용 가치에만 집중한다.

🎯
한 줄 정의 — 본인과 가족, 그리고 본인이 초대한 친구 몇 명만 쓰는 사적 요리 노트. 핵심은 "내 가족 구성원 입맛 모으기" + "유튜브에서 본 좋은 요리 정리".

08화면 와이어프레임

기존 6화면(홈/분석/상세/보정/조리/구성원)은 v0.4 그대로 유지. v0.5에서 추가될 화면:

  • 냉장고 모드 — 재료 체크리스트 + 가능한 레시피 카드
  • 컬렉션 화면 — 폴더 그리드 + 폴더 내 레시피 목록
  • 초대 관리 — 본인 가구에 누가 있는지, 초대 코드 발급/관리
  • 상황 태그 선택 — 레시피 저장 시 다중 선택 칩

와이어프레임 그림은 v0.5.1에서 디자인 시스템과 함께 추가 예정.

09공유 인텐트 처리

유튜브 + 인스타·틱톡 진입로 확장 v0.5

안드로이드 Manifest 인텐트 필터는 그대로. EXTRA_TEXT에서 URL 추출 시 정규식만 확장:

const PATTERNS = [
  // YouTube
  /(?:youtube\.com\/watch\?v=|youtu\.be\/|youtube\.com\/shorts\/)([\w-]{11})/,
  // Instagram Reels/Posts
  /instagram\.com\/(?:reel|p|tv)\/([\w-]+)/,
  // TikTok
  /(?:tiktok\.com\/@[\w.-]+\/video\/|vm\.tiktok\.com\/)(\d+|[\w]+)/,
];
function extractMedia(text) {
  for (const re of PATTERNS) {
    const m = text.match(re);
    if (m) return { platform: detectPlatform(re), id: m[1] };
  }
  return null;
}
⚠
검증 필요 — Gemini의 file_data.file_uri가 인스타·틱톡 URL을 어떻게 처리하는지 실측 필요. 직접 접근 안 되면 클라이언트가 짧은 비디오 파일 자체를 inline으로 보내는 방식으로 폴백.

Edge Function에 일일 글로벌 cap 설정 (예: 일 100회). 초과 시 캐시 결과만 반환하고 신규 분석은 다음날까지 보류. 본인 키 사용량 모니터링 자동화.
MED

캐스케이드 폴백 + 보정 모드로 흡수. 본인 사용 시작 후 한 달간 실측해서 confidence 0.5 임계값 조정.
MED
초대 토큰 유출 초대 코드가 외부로 새면 모르는 사람이 본인 Gemini 키 비용으로 분석.
invites.max_uses + expires_at 강제. 본인이 admin 화면에서 가입자 목록 보고 모르는 계정 즉시 차단. 글로벌 cap이 비용 폭증의 최후 방어선.
MED
친구 데이터 격리 오류 RLS 정책 실수로 친구가 다른 친구 데이터 볼 수 있음.
마이그레이션마다 tests/rls 자동 검증. household_id 단위 격리 테스트 케이스 필수.
LOW
친구가 안 씀 / 도구가 죽음 초대해도 안 쓸 수 있음. 그래도 본인은 매일 씀.
친구 사용은 부가 가치. 본인 사용이 1순위. 친구 활성도 KPI는 압박 X.

15운영 방침

상업화 자리를 차지한 새 섹션

초대 정책

  • 본인이 admin 화면에서 초대 코드 발급. 친구가 코드 입력 → 자기 가구 자동 생성
  • 초대 코드는 max_uses(예: 1회) + expires_at(예: 7일) 강제
  • 본인 admin 화면에서 가입자 목록 → 모르는 계정 즉시 차단
  • 가입자 총원 가이드라인: 10명 이하 (Gemini 무료 한도 안전 범위)

비용 관리

  • Gemini 일일 글로벌 cap: 초기 100회 (캐시 적중 포함 전체 분석 시도)
  • 본인 Google Cloud Billing 알림 설정 (월 ₩30,000 임계)
  • Supabase 무료 티어 한도 내 운영 (DB 500MB, Storage 1GB, Edge Functions 500K invocations/월)

법적·운영

  • 저작권: 영상 재배포 X, 출처 명시. 사적 사용 범위라 fair use 적용
  • 개인정보: 친구들에게 "본인 운영 사적 도구, Supabase에 데이터 저장, 외부 공유 X" 명시
  • 약관·정책: 공식 약관 불필요. 본인이 README에 운영 원칙만 기재

장기 출구

  • 본인이 안 쓰게 되면 → 친구들에게 데이터 export 안내 후 종료
  • 본인이 흥미 잃으면 → 코드 그대로 GitHub 공개 유지, 친구가 자기 fork로 운영 가능
  • 레시피오 등 상용 앱이 압도적으로 좋아지면 → 본인도 그쪽 이주, 우리 앱은 archive
